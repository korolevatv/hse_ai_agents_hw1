# Tasks

## 1. Доменная модель и стартовые данные (`domain.mjs`)

- [x] 1.1 Создать `domain.mjs` и реализовать модель задачи (`id`, `title`, `hours`, `done`) и фабрику стартового состояния с тремя задачами (Чтение — 2 ч, `done=true`; Практика — 4 ч, `done=false`; Повторение — 2 ч, `done=false`). Проверка: импорт модуля в Node.js возвращает корректный массив из 3 задач с ожидаемыми полями и значениями.
- [x] 1.2 Реализовать функции изменения данных: добавление задачи с генерацией `id`, удаление по `id`, переключение `done` по `id` без мутаций, нарушающих предсказуемость (чистые операции/возврат нового состояния). Проверка: unit-вызовы функций показывают фактическое изменение набора данных (длина/содержимое/флаг `done`).

## 2. Валидация и расчёт итогов (`domain.mjs`)

- [x] 2.1 Реализовать валидацию ввода задачи: `title` непустой после `trim`; `hours` — число от 0.5 до 24 с шагом 0.5; пустое значение — ошибка. Функция должна возвращать нормализованные данные или структурированные ошибки по полям. Проверка: вызовы с пустым/пробельным названием, пустыми часами, значениями вне диапазона и с неверным шагом возвращают ошибки; корректный ввод возвращает нормализованный результат.
- [x] 2.2 Реализовать расчёт итогов `totalHours`, `doneHours`, `progress` по всем задачам по формуле `округление(100 * doneHours / totalHours)`; при отсутствии задач — 0% без `NaN/Infinity`. Проверка: для стартового набора получаются 8/2/25%, после отметки «Практики» — 8/6/75%, для пустого набора — 0/0/0%.
- [x] 2.3 Реализовать фильтрацию видимого списка (`all`, `active`, `done`) как функцию над полным набором данных без изменения исходного массива. Проверка: при фильтре `active` в стартовом состоянии видимы 2 задачи, но расчёт итогов по полному набору остаётся 8/2/25%.
